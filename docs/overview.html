Why Foundry

动机决定优先级

公司环境硬约束

公司电脑不允许安装 Codex CLI / Claude Code，模型访问只能走公司 Gateway 的 API；软件分发走内部源（JFrog），Python + 内部 wheel 目录是最确定的通道。

学习目的

吃透 coding-agent runtime 的设计。此前用 Agent SDK 攒过 mini-codex 体验一般——Foundry 要赢在完全掌控与设计质量，宁窄而精。

设计优先级（冲突时按此裁决）：可审计 > 少依赖/离线可装 > 清晰实现 > 功能数量
Model Paths

三个环境，同一套 runtime

个人、公司、开发三条路径只切换认证与协议 adapter 层；loop 与 tools 完全共用。原计划的 ChatGPT 订阅登录经限定调研确认 blocked——图中虚线即被否决的路径。

Architecture

事件流驱动的核心

UI 与 runtime 第一天解耦：CLI 只是类型化事件流的第一个订阅者，审批是异步事件对而非阻塞输入——headless 模式、未来 IDE 前端因此近乎免费。SessionStore 是单一事实源，逐字节可重放。

Policy Pipeline

无沙箱时代的唯一防线

V1 是 trusted-host：审批是行为约束而非安全边界，首次运行明确披露。PolicyEngine 采纳 Claude Code Agent SDK 公开的六步评估规范，外加最先执行的硬编码熔断表。

Key Decisions

七个改变走向的决定

D-009 · 推翻草稿最高优先项

ChatGPT 登录 → blocked-with-evidence，个人路径改用 API key

  • 官方 "Sign in with ChatGPT" 只授予身份（姓名/邮箱/头像），不给推理与订阅额度，且需申请审核；
  • Codex 订阅端点 originator 白名单：非 Codex 客户端 403，用即须协议层冒充——违 OpenAI ToS 与 Foundry 章程，有封号先例；
  • OpenAI 认可的程序化路径只有平台 API key。开发验证不受影响：ReplayBackend 离线全覆盖 + 本地模型端点免费冒烟。
D-006 / D-010

多模型 Gateway ⇒ 弃 V4A，编辑格式选模型中性

V4A 是 GPT 私有训练格式，Claude 用之崩坏。apply_patch = 信封 + 锚定文本 search/replace（Claude Code / OpenHands / aider 独立收敛的方案），逐文件原子、失败带最近似行提示。

D-017

finish 工具：completed 门禁机器可验

验证声明经 finish{status, claims} 提交，runtime 与事件流交叉核验（命令事件存在、exit code 一致、HEAD 未移动）——模型口头声称"已验证"不再可能通过。

D-014 / D-018

依赖预算：运行时仅 rich（+可选 prompt_toolkit）

HTTP/SSE 自研于 stdlib（信任 Windows 系统证书库，公司 MITM 代理零配置）；DPAPI 与 Job Object 走 ctypes；shell 固定 PowerShell 5.1（预装零依赖）。

D-004 / D-012

交互式优先；schema 第一天可重放

核心形态是终端会话，UI 与 loop 解耦。session JSONL 可逐字节重建每次模型请求——resume 功能推 V2，但 schema 不欠债。

D-011 / D-019 / D-020

脏工作区、仓库说明文件、验收基准

脏工作区警告继续 + 脏文件写强制 ASK；FOUNDRY.md 声明测试命令（信任门控，M2）；golden 任务集跑在自建样例仓 fixture 上，是改 prompt/loop 的回归基准。

D-022 / D-024 · 吸收自平行蓝图

Gateway 情报落地 + 13 项工程要点

OpenAI 系走 Responses、token 来自内网 auth ⇒ responses adapter 升为 M3 必选，入场门 = 先取 tool-call 流式夹具。另吸收：canary 泄漏套件、崩溃恢复语义、内容寻址 artifacts、失败指纹、审批绑定有效期、变更归属分离报告。

Roadmap

每个里程碑以"可运行 + 可验收"收口

排序原则：最大不确定项不上关键路径。全部 233 个测试在无网络、无凭证的机器上通过；真实运行已验证：agent 跑失败测试 → 读文件 → 打补丁 → 重跑测试转绿 → 带证据收口，exit 0。

  • M0Walking skeleton · 接口冻结 ✓
    IR / 事件协议 / ModelBackend / session 信封四接口已冻结；replay backend + foundry record 夹具重录就绪。
  • M1a文件工具 + Policy 流水线 ✓
    apply_patch（逐文件原子 + 宽容梯度）、workspace 边界、六步流水线、审批 UI、脏工作区策略。攻击表与决策表全绿。
  • M1brun_command + 命令分段器 ✓
    Job Object 进程树（实测无孤儿残留）、env 过滤、编码回退；分段器 + 熔断表全表 + audit.jsonl。
  • M2个人路径 E2E + 验收任务集 ✓
    login/DPAPI、错误分类学、finish 证据链、FOUNDRY.md、8 个 golden 场景、foundry report 遥测。
  • M3公司 Gateway 部分
    responses adapter + 12 项合同测试已就绪，流式降级已实现；入场门未过——真实 Gateway 的 tool-call 流式夹具待取（OQ-6）。
  • M4打包加固 + 披露 ✓
    净 venv --no-index 安装实测通过（5 个纯 py wheel）；威胁模型文档；foundry exec 已进 V1。
  • V2候选池
    session resume · LLM 摘要压缩 · update_plan · skills · subagent seam · MCP 桥 · shadow-git checkpoint。
