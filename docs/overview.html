Foundry.

A local coding-agent runtime built from scratch — owning all of the code and interfaces for its loop, tools, policy, providers and sessions.

It does not fork, call into, or impersonate any existing coding agent; it studies the published designs of Codex / Claude Code / gemini-cli / aider / OpenHands, borrows the best of them, and then implements its own.

Why Foundry

The motivation decides the priorities

Hard corporate constraints

Corporate machines may not install Codex CLI or Claude Code, and model access must go through the corporate Gateway's API; software distribution goes through an internal source (JFrog), and Python plus an internal wheel directory is the most certain channel.

Learning

To understand coding-agent runtime design thoroughly. A mini-codex assembled earlier with the Agent SDK was a mediocre experience — Foundry has to win on complete control and design quality: narrow, but good.

Design priorities (used to resolve conflicts): auditability > few dependencies / offline installable > a clear implementation > feature count
Model Paths

Three environments, one runtime

The personal, corporate and development paths differ only in the authentication and protocol adapter layers; the loop and the tools are entirely shared. The originally planned ChatGPT subscription login was confirmed blocked by bounded research — the dashed line below is that rejected path.

Architecture

An event-stream-driven core

The UI and the runtime are decoupled from day one: the CLI is merely the first subscriber to a typed event stream, and approval is an asynchronous event pair rather than a blocking input — which makes headless mode, and a future IDE front end, nearly free. SessionStore is the single source of truth, replayable byte for byte.

Policy Pipeline

The only line of defence in a sandbox-free world

V1 is a trusted host: approval is a behavioural constraint, not a security boundary, and the first run says so plainly. PolicyEngine adopts the six-step evaluation specification published with the Claude Code Agent SDK, plus a hard-coded breaker table that runs before all of it.

Key Decisions

Seven decisions that changed the direction

D-009 · overturning the draft's top priority

ChatGPT login → blocked-with-evidence; the personal path uses an API key

  • The official "Sign in with ChatGPT" grants identity only (name/email/avatar), not inference or subscription quota, and requires an application review;
  • the Codex subscription endpoint has an originator allowlist: a non-Codex client gets 403, so using it means impersonation at the protocol level — a violation of OpenAI's ToS and of Foundry's charter, with real bans on record;
  • the only programmatic route OpenAI endorses is a platform API key. Development verification is unaffected: ReplayBackend covers everything offline, and a local model endpoint gives free smoke tests.
D-006 / D-010

A multi-model Gateway ⇒ drop V4A for a model-neutral edit format

V4A is a GPT-private trained format and Claude mangles it. apply_patch is an envelope + anchored-text search/replace (the approach Claude Code, OpenHands and aider converged on independently), atomic per file, with the nearest matching line quoted on failure.

D-017

The finish tool: a machine-verifiable completed gate

Validation claims are submitted through finish{status, claims}, and the runtime cross-checks them against the event stream (the command event exists, the exit code matches, HEAD has not moved) — a model simply asserting "verified" can no longer pass.

D-014 / D-018

The dependency budget: only rich at runtime (+ optional prompt_toolkit)

HTTP/SSE is written on the stdlib (trusting the Windows system certificate store, so a corporate MITM proxy needs no configuration); DPAPI and Job Objects go through ctypes; the shell is fixed as PowerShell 5.1 (preinstalled, zero dependencies).

D-004 / D-012

Interactive first; a replayable schema from day one

The core form is a terminal session, with the UI decoupled from the loop. The session JSONL can rebuild every model request byte for byte — the resume feature is deferred to V2, but the schema takes on no debt.

D-011 / D-019 / D-020

Dirty working trees, the repository instruction file, and the acceptance baseline

A dirty working tree warns and continues, with a forced ASK on writes to dirty files; FOUNDRY.md declares the test commands (trust-gated, M2); the golden task set runs against a sample-repository fixture we build, and is the regression baseline for prompt and loop changes.

D-022 / D-024 · absorbed from a parallel blueprint

The Gateway intelligence, plus 13 engineering points

The OpenAI family goes through Responses and the token comes from intranet auth ⇒ the responses adapter becomes mandatory for M3, with the entry gate being the tool-call streaming fixtures. Also absorbed: the canary leak suite, crash recovery semantics, content-addressed artifacts, failure fingerprints, approval binding and expiry, and a report that separates attribution.

post-implementation · adversarial review rounds 1–5

Four rounds all broke the command segmenter — so denial stopped depending on it

  • Enumerating dangerous spellings cannot keep up: patch &'foo' and along comes (git reset --hard); add comment stripping and along comes a<# ; … #> (which PowerShell executes and the stripper erased);
  • worse, the fixes created new defects: 3 of the 4 criticals came out of the previous round's fixes, and twice they downgraded an "unapprovable DENY" into an "approvable ASK";
  • the structural answer: the breaker table additionally scans a deliberately wrong reading — ignoring quotes, comments and grouping, adding only denials and never allowances, and so making no assumption that can be fooled; the auto-approval side was tightened to a small verifiable syntax;
  • and 540 generated invariant combinations hold the line that "no decoration can make a forbidden command approvable", defending a whole class of mistake rather than the spellings someone thought of.
round 6 · the clean-room check

The defect was not inside a layer, but on the seam between two

  • The patch tool knows AVERYL~1.PY and the long name are the same file; the policy layer compares strings, so an 8.3 alias walked past the dirty-file guard — the one rule whose entire reason to exist is overriding accept_edits;
  • encoding was chosen by "which produced fewer replacement characters", and the fallback code page maps all 256 bytes and can never produce a replacement character: one bad byte turned the whole output into mojibake, and output was already cut by byte at the capacity ceiling;
  • the system prompt told the model "a merge is always refused", and git pull does exactly that merge yet walked straight past the breaker table — the prompt is now generated from the breaker table's constants, with a two-way alignment test;
  • the sharpest one was caught by the clean-room check, not the test suite: a credential fell across two streamed deltas, neither fragment matched, and the renderer reassembled it on screen — a clean event stream and a leaking terminal.

A cross-layer property has to be verified across layers. It closed on a real clean-room end-to-end: rebuild the wheelhouse → install into a fresh venv with --no-index → run a real task, with all 14 checks passing.

Roadmap

Every milestone closes on "runnable + acceptable"

The ordering principle: the largest uncertainty never sits on the critical path. All 1111 tests pass on a machine with no network and no credentials; and a real run is verified: the agent runs failing tests → reads the files → patches → re-runs the tests green → closes out with evidence, exit 0.

  • M0Walking skeleton · interfaces frozen ✓
    The four interfaces (IR / the event protocol / ModelBackend / the session envelope) are frozen; the replay backend and foundry record fixture re-recording are ready.
  • M1aFile tools + the policy pipeline ✓
    apply_patch (per-file atomic + a leniency gradient), the workspace boundary, the six-step pipeline, the approval UI, and the dirty working-tree policy. The attack and decision tables are green.
  • M1brun_command + the command segmenter ✓
    Job Object process trees (no orphans left in practice), env filtering, encoding fallback; the segmenter + the full breaker table + audit.jsonl.
  • M2Personal path E2E + the acceptance task set ✓
    login/DPAPI, the error taxonomy, the finish evidence chain, FOUNDRY.md, 8 golden scenarios, and foundry report telemetry.
  • M3Corporate Gateway partial
    The responses adapter and 12 contract tests are ready, and the streaming downgrade is implemented; the entry gate is not passed — the real Gateway's tool-call streaming fixtures are still needed (OQ-6).
  • M4Packaging hardening + disclosure ✓
    A clean venv --no-index install passes in practice (5 pure-py wheels); the threat model is documented; foundry exec made V1.
