# ChatGPT auth feasibility

## Verdict
UNSUPPORTED for the actual goal (consuming a personal ChatGPT Plus/Pro subscription for MODEL INFERENCE from a non-Codex third-party tool): OpenAI offers no sanctioned mechanism. "Sign in with ChatGPT" is officially-supported but grants IDENTITY ONLY (name/email/picture), not inference or subscription quota. The only OpenAI-sanctioned inference paths are a platform API key (pay-per-token, not the subscription) or official Codex surfaces (CLI/IDE/SDK) — and wrapping/invoking Codex is forbidden by Foundry's own charter. Reusing Codex's OAuth client_id to spend subscription quota is unsupported, breaches OpenAI's Terms, is actively blocked (originator whitelist + Cloudflare 403), and risks account bans. Recommendation: treat the personal-subscription-inference path as BLOCKED; ship an API-key backend for the personal path.

## Evidence

- 'Sign in with ChatGPT' launched as live beta on 2026-08-02 with six partners (Airtable, GitLab, HubSpot, Notion, Supabase, Vercel). Per OpenAI Help Center it is an IDENTITY provider: 'only your name, email, and profile picture (if you have one) are shared with the partner.' It grants NO model inference and NO subscription quota. https://help.openai.com/en/articles/20001410-sign-in-with-chatgpt
- Sign in with ChatGPT uses OAuth 2.1 + OIDC via the Apps SDK, 'with ChatGPT acting as the OAuth public client on behalf of the user, while your backend serves as the protected resource' — i.e. OpenAI is the IdP, the third party must still supply its own resource/model backend. https://help.openai.com/en/articles/20001410-sign-in-with-chatgpt ; https://developers.openai.com/chatgpt
- Developer participation in Sign in with ChatGPT is NOT self-serve: it is via an application/interest form ('A developer interest form on OpenAI's website invites apps of all sizes... to apply', asking how they charge for AI and whether they already use OpenAI APIs). OpenAI reviews responses before enabling partners. https://techcrunch.com/2025/05/27/openai-may-soon-let-you-sign-in-with-chatgpt-for-other-apps/ ; https://www.medianama.com/2025/06/223-openai-sign-in-with-chatgpt-third-party-apps/
- Codex CLI's ChatGPT OAuth client_id is PUBLIC in openai/codex source: CLIENT_ID = "app_EMoamEEZ73f0CkXaXp7hrann" (codex-rs/login/src/auth/manager.rs), override env var CODEX_APP_SERVER_LOGIN_CLIENT_ID. Issuer https://auth.openai.com; authorize /oauth/authorize; token /oauth/token; revoke /oauth/revoke. https://github.com/openai/codex (codex-rs/login/src/auth/manager.rs)
- Codex OAuth is PKCE (code_challenge_method S256), localhost redirect http://localhost:1455/auth/callback (fallback 1457), scopes 'openid profile email offline_access api.connectors.read api.connectors.invoke', plus params id_token_add_organizations=true, codex_cli_simplified_flow=true, originator=<value>. Source: codex-rs/login/src/server.rs. https://github.com/openai/codex
- Codex model traffic (ChatGPT-plan auth mode) goes to the private endpoint https://chatgpt.com/backend-api/codex/responses — NOT api.openai.com/v1. Regular API keys fail there; OAuth tokens fail on /v1/chat/completions. Required headers include Authorization: Bearer <access_token>, ChatGPT-Account-ID, originator, User-Agent codex_cli_rs/..., OpenAI-Beta. https://gist.github.com/ravidsrk/4e72b774c044917cd260560ec5831e1d ; https://github.com/simonw/llm-openai-via-codex
- The backend ACTIVELY BLOCKS non-Codex originators: the endpoint whitelists first-party originators (codex_cli_rs, codex_vscode, codex_sdk_ts, or anything starting with 'Codex'); a client sending originator: pi gets 403 Forbidden on every request (pi-mono issue #1828, 2026-03-05). Independent Cloudflare 403 blocks also reported on this endpoint (openai/codex issue #18688). https://github.com/badlogic/pi-mono/issues/1828 ; https://github.com/openai/codex/issues/18688
- OpenAI Terms of Use (Restrictions section) prohibits: 'use any automated or programmatic method to extract data or output from the Services, including scraping, web harvesting, or web data extraction' — 'except as permitted through the API'; and prohibits 'interfering with or disrupting the Services, including circumventing any rate limits or restrictions or bypassing any protective measures or safety mitigations'; and reverse-engineering to 'discover the source code or underlying components.' Spoofing the Codex originator to spend subscription quota implicates all three. https://openai.com/policies/row-terms-of-use/ ; https://ospo.co/blog/be-careful-with-openais-terms-of-use/
- OpenAI's own Codex docs designate the sanctioned programmatic path as the API key, not the subscription: 'use API key authentication for programmatic Codex CLI workflows, such as CI/CD jobs,' while 'some features that rely on ChatGPT workspace access or cloud services are limited or unavailable.' ChatGPT-plan usage is described only for 'local clients such as the CLI and IDE extension' and web/cloud. https://learn.chatgpt.com/docs/auth ; https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan
- Community tools that DO reuse Codex OAuth all carry self-authored disclaimers admitting it is not for third-party/production use: e.g. numman-ali/opencode-openai-codex-auth README: 'This plugin is for personal development use with your own ChatGPT Plus/Pro subscription. For production or multi-user applications, use the OpenAI Platform API.' https://github.com/numman-ali/opencode-openai-codex-auth
- Enforcement precedent + account risk: OpenAI has 'had to block various unofficial API wrappers and client apps over the years'; Anthropic blocked equivalent subscription-token relay in April 2026 and Google did the same with Gemini CLI. Multiple 2026 reports of ChatGPT Pro/Codex account bans, some correlated with third-party proxy (CLIProxyAPI) use. https://www.mindstudio.ai/blog/openai-codex-anthropic-subscription-change ; https://community.openai.com/t/codex-chatgpt-pro-account-banned-with-no-warning-no-explanation-18-month-subscriber/1381906
- OpenAI Apps SDK submission guidelines: OpenAI 'cannot approve apps that primarily function as unofficial connectors to third-party services, including pass-through middleware layers' — directly adverse to a Foundry backend that pass-throughs ChatGPT-plan inference. https://developers.openai.com/apps-sdk/app-submission-guidelines
- Sign in with ChatGPT plan eligibility (for the identity login) is Free/Plus/Pro (Enterprise now included per help center; earlier Team/Edu/Enterprise excluded). Codex-plan sign-in gives Plus users $5 and Pro users $50 in one-time API credits (30-day), which are API credits — reinforcing that real programmatic inference is expected to run on the platform API, not the subscription. https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan

## Options

### (a) Apply to official 'Sign in with ChatGPT' program
- Pros: Fully legitimate, officially-supported; standards-based OAuth 2.1/OIDC; gives Foundry a real user-identity login tied to the user's ChatGPT account; low ToS risk.
- Cons: DOES NOT SOLVE THE STATED GOAL. It grants identity only (name, email, profile picture) — no model inference, no subscription quota, no access to chatgpt.com/backend-api. Foundry would still need a separate inference backend (API key or corporate gateway). Not self-serve: application/interest-form + OpenAI review; partner slots so far are large ecosystem players.
- Risk: Low legal/ToS risk. But it is the wrong tool for inference: approval yields zero inference capability, so it cannot be the personal inference path. Useful only if Foundry wants 'log in with your OpenAI identity' UX.

### (b) Reuse Codex's public OAuth client_id (app_EMoamEEZ...) + spoof originator to hit chatgpt.com/backend-api/codex/responses
- Pros: Technically works today for personal use; no per-token cost (spends the user's existing Plus/Pro allowance); client_id and flow are public in openai/codex source; several community plugins prove feasibility.
- Cons: Requires impersonating Codex (sending originator codex_cli_rs / Codex-prefixed UA) — the endpoint whitelists first-party originators and returns 403 to anything else, so Foundry MUST pretend to be Codex to work at all. That directly violates Foundry's charter ('must not fork, vendor, wrap, or invoke Codex... only learn from public source/design') and is not 'without being Codex' — it is being Codex on the wire. Undocumented private endpoint + hardcoded client_id OpenAI can revoke anytime; fragile (recurring Cloudflare/originator/header breakages).
- Risk: HIGH / UNSUPPORTED. Breaches OpenAI Terms of Use: programmatic extraction of Output outside the API, circumventing restrictions, and bypassing protective measures (the originator whitelist is a protective measure). Documented account-ban risk. Reputationally it is exactly the 'sneaky workaround' the user rejects. Do NOT implement.

### (c) OpenAI Platform API key (pay-per-token)
- Pros: Fully sanctioned and documented as THE programmatic path; stable public endpoint (api.openai.com/v1, Responses/Chat Completions); no impersonation; full model catalog per account; clean fit for Foundry's swappable ModelBackend; no ToS gray area.
- Cons: Not the ChatGPT subscription — it is a separate billing relationship; the user pays per token on top of any Plus/Pro they hold; requires the user to create/hold a platform account and key (a credential Foundry must handle carefully, never entered by the agent itself).
- Risk: Lowest risk. Officially supported, terms-compliant, durable. This is the correct 'personal path' for real inference.

### (d) Official Codex SDK / Codex CLI as an inference backend (ChatGPT-plan auth)
- Pros: The ONLY OpenAI-sanctioned way to run inference against a ChatGPT Plus/Pro subscription; TypeScript SDK / app-server exists to embed the Codex agent; uses the official login and originator, so no ToS breach and no ban risk.
- Cons: Excluded by Foundry's charter, which forbids forking/vendoring/wrapping/invoking Codex or Claude Code. Also drags in the Codex agent harness/prompts rather than Foundry's own loop; Node.js runtime dependency; ties Foundry to Codex's model set and surface.
- Risk: Low ToS risk but charter-blocked. Cannot be used without redefining Foundry as a Codex wrapper — which the project explicitly prohibits.

### (e) Corporate OpenAI-Responses-compatible gateway (already in Foundry's plan)
- Pros: Sanctioned by the corporate relationship; Responses-compatible so it slots into Foundry's ModelBackend abstraction; no personal-subscription ToS issue; enterprise-grade.
- Cons: Not a 'personal ChatGPT subscription' path at all — it is the corporate backend; requires corporate gateway credentials/entitlement; unavailable to a purely personal user.
- Risk: Low. Legitimate for the corporate backend; simply does not answer the personal-subscription question.


## Recommendation
Treat the personal-ChatGPT-subscription-for-inference path as BLOCKED, and document it as 'blocked with evidence' exactly as the user wants. There is no officially supported way for a non-Codex third-party tool to consume Plus/Pro subscription quota for model inference: OpenAI deliberately gates that behind first-party Codex surfaces (originator whitelist on chatgpt.com/backend-api/codex/responses returns 403 to non-Codex clients — a protective measure the ToS forbids circumventing). 'Sign in with ChatGPT' is a real, supported program but is IDENTITY-ONLY (name/email/picture) and grants no inference, so it cannot back Foundry's models even if approved. Concretely: (1) For Foundry's PERSONAL ModelBackend, implement option (c) — the OpenAI Platform API key (Responses/Chat Completions on api.openai.com), pay-per-token — as the only terms-compliant, durable personal path. Never have the agent type the key; take it via env/config or a credential tool. (2) For the CORPORATE path keep option (e), the Responses-compatible gateway (already planned). (3) Do NOT implement option (b) client_id reuse/originator spoofing: it requires impersonating Codex on the wire (violating both OpenAI's Terms — programmatic Output extraction outside the API, circumventing restrictions, bypassing protective measures — and Foundry's own 'must not wrap/invoke Codex' charter) and carries real account-ban risk. (4) Optionally add option (a) purely as a 'Sign in with your OpenAI identity' UX feature, clearly separated from inference, if/when OpenAI accepts Foundry's interest-form application — but it does not reduce the need for an API key. Bottom line for the user: the honest answer is NO — a brand-new tool cannot legitimately turn a personal ChatGPT Plus/Pro subscription into model inference without being Codex; the supported alternatives are a platform API key or the corporate gateway.
