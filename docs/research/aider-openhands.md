# Aider + OpenHands + SWE-agent

## Summary

Across aider, OpenHands, and SWE-agent/mini-swe-agent, the single strongest convergent finding is that file-editing reliability is dominated by the *representation* the model emits and the *forgiveness* of the applier, not by model intelligence. Aider's benchmarks show edit-format compliance is a distinct skill from coding ability: GPT-3.5 could only reliably return whole files (46% whole vs 30% diff), GPT-4-class models handle SEARCH/REPLACE blocks, GPT-4-Turbo's laziness was cut 3x by switching to a line-number-free unified-diff format (20%→61% on an 89-task refactor benchmark), and putting code inside JSON degrades every model tested (escaping errors produce syntax-broken code). On the applier side, aider's flexible matching pipeline (exact match → leading-whitespace-tolerant → dropped-blank-line → "..." elision handling → ~80%-similarity fuzzy) matters enormously: disabling flexible patching caused a 9x increase in editing errors. Failed edits must return actionable feedback (aider emits the failed block plus "similar lines" hints; SWE-agent found agents recover from a first failed edit 90.5% of the time but success collapses to 57.2% as failures accumulate).

SWE-agent's ACI ablations quantify tool ergonomics: a 100-line file-view window beats both 30 lines (-3.7pts) and full-file (-5.3pts); a lint guardrail that auto-reverts syntactically-invalid edits is worth +3.0pts; search tools that cap output at 50 summarized results beat iterative one-at-a-time viewing by +6.0pts; collapsing observations older than the last 5 to one line beats retaining full history by +3.0pts. The meta-lesson: concise, consolidated, guard-railed tools with informative-but-terse feedback measurably raise success rates, and resolved tasks finish fast (median 12 steps) — bigger budgets don't rescue failing trajectories. Then mini-swe-agent demonstrates the ceiling of minimalism: ~100 lines of agent code, bash-only, no tools/tool-calling, each step an independent stateless subprocess.run, purely linear append-only message history — yet >74% on SWE-bench Verified with frontier models. Much of 2024's scaffolding complexity has been obsoleted by better models; what survives is the edit tool, the feedback loop, and budget/stop discipline.

OpenHands contributes the architecture pattern that matches Foundry's SessionStore: an immutable, chronological event stream of Action/Observation events from which agent state is derived; agents are a pure step(state)→action function. Its context condenser (LLMSummarizingCondenser: trigger at max_size≈120 events, keep_first≈4 verbatim, summarize the middle, record a Condensation event carrying forgotten_event_ids + summary into the immutable log so views are reconstructed deterministically) halves API cost with no accuracy loss (54% vs 53% on SWE-bench subset). But the 2025 "Complexity Trap" paper (arXiv 2508.21433) shows simple observation masking matches LLM summarization on cost and solve rate — evidence that Foundry V1 can skip the summarizer LLM entirely. OpenHands' Docker action-execution-server runtime and multi-agent delegation are the pieces Foundry explicitly should not copy for a trusted-host Windows V1; note also that OpenHands itself migrated file editing from IPython-executed AgentSkills edit_file toward a server-side str_replace editor — converging on the same exact-string-replace primitive from a different direction.

## Designs

### Primary edit format (apply_patch representation)
- **How**: Aider's default for capable models is SEARCH/REPLACE blocks: file path line, then <<<<<<< SEARCH / ======= / >>>>>>> REPLACE fences containing exact existing text and replacement (aider/coders/editblock_coder.py, aider.chat/docs/more/edit-formats.html). 'whole' (full file) is the fallback for weak models; 'udiff' (unified diff with @@ ... @@ hunks whose line numbers are IGNORED — each hunk applied as search/replace on context lines) was built because GPT-4-Turbo elided code; 'diff-fenced' exists only because Gemini misplaces the filename. OpenHands independently converged on str_replace exact-string editing (PR #6671).
- **Takeaway**: COPY: make apply_patch accept exact-text search/replace hunks (optionally in udiff clothing) and never trust line numbers from the model — treat every hunk as context-anchored search/replace. ADAPT: since Foundry targets modern frontier models via tool calls, support one canonical format, not aider's six; keep 'whole file' as an explicit escape hatch for small files/weak gateway models. REJECT: line-number-addressed edits (OpenHands' original edit_file line-based API was abandoned) and multiple dialects per model.

### Plain text vs structured/JSON edit payloads
- **How**: Aider's code-in-json benchmark (aider.chat/2024/08/14/code-in-json.html, 133 exercises, Sonnet/DeepSeek/GPT-4o) found every model scores worse returning code wrapped in JSON — escaping (\' vs \\', \n) yields syntax errors — and OpenAI strict mode didn't help. The 2023 benchmark post found function-call edit formats underperformed plain text for both GPT-3.5 and GPT-4.
- **Takeaway**: ADAPT carefully: Foundry's apply_patch is a tool call, so the patch text will transit JSON string escaping. Mitigate: (1) keep the patch in ONE opaque string argument (never structured per-hunk JSON fields), (2) tolerate common escape damage in the applier, (3) verify empirically per backend — the corporate Responses gateway and personal OpenAI both now train heavily on tool-call editing, so 2024's penalty is smaller, but the 'one big string, minimal schema' rule still holds.

### Forgiving patch application pipeline
- **How**: aider's replace_most_similar_chunk tries, in order: perfect match; match ignoring leading-whitespace deltas (compute common indent, strip, re-apply); drop spurious leading blank lines; try_dotdotdots for '...' elided sections; fuzzy match at >80% similarity. The udiff post reports disabling this flexibility caused a 9x increase in editing errors; hunks are also split around unchanged context to increase match odds.
- **Takeaway**: COPY the ladder through whitespace-normalization and blank-line tolerance — on Windows add CRLF/LF and BOM normalization as the FIRST rung (this will be Foundry's #1 real-world failure mode). ADAPT: gate or drop the 80%-similarity fuzzy rung — silent fuzzy application can edit the wrong site; prefer fail-with-hint. COPY '...' elision support only if using udiff-style hunks.

### Failed-edit feedback loop
- **How**: aider returns a structured error naming how many blocks failed vs succeeded, echoes the failed SEARCH text, and appends find_similar_lines() output ('did you mean') from the actual file, without re-applying successful blocks. SWE-agent measured recovery: 90.5% eventual success after one failed edit, 57.2% after accumulated failures — errors compound fast.
- **Takeaway**: COPY exactly: on partial patch failure, apply the good hunks, report per-hunk status, quote the nearest-matching real file lines, and instruct the model to resend ONLY failed hunks. Cap consecutive edit failures on one file (2-3) then force a read_file — this is cheap and directly attacks the error-compounding curve.

### Post-edit lint/test guardrail
- **How**: SWE-agent lints every edit with flake8 (undefined names F821/F822, dup args F831, indent E111-E113, syntax E999) and auto-reverts invalid edits with a before/after snippet; removing this costs 3.0 points (18.0%→15.0%), and having no dedicated edit command at all costs 7.7 points. aider auto-lints edited files (built-in per-language linters, --lint-cmd override), optionally runs --test-cmd after each edit, and feeds nonzero-exit output back to the model for repair.
- **Takeaway**: COPY: after apply_patch, run a fast syntax check on changed files (Python: compile()/pyflakes — pure-Python, wheel-friendly) and include failures in the tool result; make revert-on-syntax-error an option. ADAPT aider's hooks as config: lint_cmd/test_cmd strings run via run_command under PolicyEngine, with auto-fix loop bounded (aider bounds reflection loops similarly). This is the highest-ROI reliability feature per line of code.

### Git as the undo/safety layer
- **How**: aider auto-commits every LLM edit with a generated Conventional-Commits message (produced by a weak model from the diff), first committing any pre-existing dirty changes separately so user work is never mixed with AI work; /undo reverts the last AI commit; authorship is attributed with '(aider)' name suffix / optional Co-authored-by; --no-auto-commits exists but is discouraged (aider.chat/docs/git.html).
- **Takeaway**: ADAPT: Foundry already has git_status/git_diff; add opt-in auto-commit (default OFF for a corporate trusted-host tool — auto-committing to work repos surprises users and CI hooks) but ALWAYS snapshot before first edit of a dirty file (stash-like ref or dirty-commit) and expose an undo. COPY the attribution trailer and weak-model commit messages. The deeper lesson to copy: never make an edit you cannot mechanically revert.

### Repo map / codebase context
- **How**: aider builds a repo map with tree-sitter: extract definitions and full signatures per file, build a graph of files/symbols weighted by cross-references, PageRank it, then greedily fill a token budget (--map-tokens, default 1k) with the top-ranked signatures; it replaced ctags because tree-sitter gives richer signatures (aider.chat/2023/10/22/repomap.html).
- **Takeaway**: ADAPT, deferred: a ranked signature map is real value but tree-sitter language wheels complicate offline pip install on Windows. V1: rely on list_files + search_text + read_file (SWE-agent's ablation shows search tools are worth only +2.3 points when navigation is otherwise good; mini-swe-agent gets >74% with none). V1.5: add a Python-only map via stdlib ast (no native deps) with a hard token budget. REJECT PageRank until a flat signature list proves insufficient.

### Agent loop and session architecture (event stream)
- **How**: OpenHands: an append-only chronological event stream of Action/Observation events; State (cost accumulators, delegation metadata) plus history are derived from the stream; agents implement step(state)->action; everything is serializable and replayable (arXiv 2407.16741). mini-swe-agent goes further: the message list IS the state — purely linear append-only history, no rewriting, which makes trajectories identical to prompts (great for debugging/fine-tuning).
- **Takeaway**: COPY: this validates Foundry's versioned-JSONL SessionStore — make it the single source of truth: every model call, tool action, tool observation, policy decision (ALLOW/ASK/DENY + reason), and any future condensation written as typed, versioned events; derive the prompt deterministically from the log. COPY mini's invariant that the log replays to exactly what the model saw. This gives resume, audit (crucial for a corporate gateway), and debugging for free.

### Context management / condenser
- **How**: OpenHands LLMSummarizingCondenser: triggers when events exceed max_size (default 120), keeps keep_first (default 4) events verbatim plus the recent tail, summarizes the middle with a (cheaper) LLM, and writes a Condensation event {forgotten_event_ids, summary, summary_offset} into the immutable log; View.from_events() rebuilds the LLM view; measured ~2x cost reduction at equal solve rate (54% vs 53%) (docs.openhands.dev/sdk/arch/condenser; openhands.dev blog 2025-04-09). SWE-agent instead collapses observations older than the last 5 to a single line (+3.0 points vs full history). arXiv 2508.21433 ('The Complexity Trap') shows plain observation masking matches LLM summarization (with Qwen3-Coder 480B: +2.6% solve rate vs unmanaged, 52% cheaper).
- **Takeaway**: COPY the mechanism shape (condensation as an event in the log, view derived deterministically) but ADAPT the policy: V1 should ship observation masking/truncation — elide tool observations older than the last N (~5) turns to a one-line stub ('output elided; re-run tool if needed'), keep system+task+recent tail intact. REJECT LLM summarization for V1: extra model dependency, awkward through a corporate gateway, and evidence says masking is as good. Also hard-cap every tool observation at write time (SWE-agent: 'informative but concise').

### Tool ergonomics (ACI): windows, caps, consolidation
- **How**: SWE-agent ablations on SWE-bench Lite (GPT-4 Turbo, base 18.0%): file viewer at ~100 lines with line numbers + omitted-line counts beats 30-line (-3.7) and full-file (-5.3); search returning ≤50 summarized results beats iterative single-result viewing (-6.0); shell-only baseline scores 11.0% vs 18.0% with the ACI. Design principles: few consolidated actions, simple docs, compact feedback, guardrails (arXiv 2405.15793).
- **Takeaway**: COPY the numbers as defaults: read_file returns a windowed view (~100-250 lines) with line numbers, total-line count, and 'N lines omitted' markers; search_text caps matches (~50) and says 'too many matches, narrow the query' instead of truncating silently; list_files caps depth/entries. COPY the doc principle: each Foundry tool description should be a short paragraph with one example, not a man page. This is where Foundry's ergonomics budget should go instead of adding more tools.

### Minimalism budget — what NOT to build
- **How**: mini-swe-agent: ~100-line agent class, bash-only (no tool-calling — action parsed from a fenced code block), every action an independent subprocess.run (no persistent shell — 'significant stability benefits', sandbox swap = replace one function), linear history, completion signaled by the model echoing a magic string; deliberately omits configurable toolsets, history processors, retrieval, multi-agent; >74% SWE-bench Verified. Philosophy: 'just tell the LM to figure it out rather than implement it in the agent.' SWE-agent data agrees on budgets: resolved tasks are fast (median 12 steps, $1.21); 93% of solved instances finish before budget exhaustion — failing runs don't get rescued by more steps.
- **Takeaway**: COPY the discipline: Foundry's 8 tools are already near the right size — resist adding more before ablation evidence; implement run_command stateless (fresh subprocess per call, cwd+env passed explicitly, no persistent PowerShell session — persistent shells are the top flakiness source and are worse on Windows). COPY hard budgets: max steps, max cost, per-command timeout, and stop early rather than raising limits. REJECT for V1: multi-agent delegation, browser tools, RAG/embeddings, architect/editor dual-model mode, LLM-summarizing condensers, plugin systems. One caveat: do NOT copy bash-only literally — on Windows with tool-calling backends, dedicated read/patch tools outperform shell text-editing (SWE-agent's no-edit-tool ablation: -7.7 points; sed/heredoc idioms in model priors break on PowerShell).

### Runtime isolation and the trusted-host stance
- **How**: OpenHands runs every session in a Docker sandbox containing a REST 'action execution server' hosting bash, a Jupyter/IPython kernel, and a Playwright Chromium; arbitrary user images get the server injected at build time. mini-swe-agent achieves isolation trivially because its environment interface is one execute() function — swap subprocess.run for docker exec.
- **Takeaway**: REJECT Docker (unavailable/heavy on corporate Windows, contradicts offline wheel install) but COPY both structural ideas: (1) put ALL side-effecting execution behind one narrow Environment interface (execute(command, cwd, timeout) -> output) so a future sandbox (Windows AppContainer, restricted token, or remote runner) is a one-class swap; (2) compensate for no-sandbox with the PolicyEngine as the real boundary — ASK on writes outside the workspace root, DENY known-destructive patterns, log every ALLOW decision to the session store. Honest V1 disclosure plus mechanical revertability (git snapshot) is the right trade; document it.

### Model-specific format capability tiers
- **How**: Aider maintains per-model edit-format defaults because compliance varies: GPT-3.5-class → whole; GPT-4/Claude → diff; GPT-4-Turbo → udiff (laziness); Gemini → diff-fenced. Architect mode (aider.chat/2024/09/26/architect.html) showed pairing a reasoning 'architect' with a format-reliable 'editor' model raised o1-preview to 85%, and even self-pairing lifted Sonnet 80.5% vs solo — proving format compliance is a separable skill.
- **Takeaway**: ADAPT minimally: give each ModelBackend profile an edit-capability field (patch | whole-file) and a retry policy, not six formats. If the corporate gateway serves a weaker/older model, fall back to whole-file for that backend rather than debugging mangled patches. REJECT dual-model architect/editor for V1 (2x cost/latency, config surface); revisit only if patch-failure telemetry from the session store shows a specific backend failing at formatting rather than reasoning.

### Failure telemetry as the improvement loop
- **How**: All three projects improved by measuring: aider built a benchmark harness and re-ran every format change (e.g., 9x error delta from flexible matching, 3x laziness reduction from udiff); SWE-agent published per-feature ablations; OpenHands validated the condenser on SWE-bench before defaulting it.
- **Takeaway**: COPY the practice cheaply: since every patch attempt, failure reason, retry count, and lint outcome is already in Foundry's JSONL SessionStore, ship a small offline report script (patch first-try success rate, failure taxonomy per backend, steps/cost per task). Decisions like 'add repo map', 'enable fuzzy rung', 'switch a backend to whole-file' should be driven by these numbers, not intuition — this is the cheapest lesson in the whole corpus.


## Risks

- Windows transfer risk: every quantitative result cited (SWE-agent ablations, aider benchmarks, mini-swe-agent scores) was measured on POSIX. Model priors reach for bash/sed/heredocs; on PowerShell/cmd these fail with confusing quoting errors. Mitigation: make apply_patch ergonomic enough that models never edit files via run_command, and state the shell explicitly (name, quoting rules, cwd) in the system prompt.
- Line-ending and encoding hazards: CRLF vs LF, UTF-8 BOM, and cp1252 files will break exact-match search/replace far more often on Windows than in any upstream project's test data. Patch application must normalize line endings for matching but preserve the file's original EOL style and encoding on write, or Foundry will corrupt files while 'succeeding'.
- Era mismatch of evidence: SWE-agent's ablations are GPT-4-Turbo (2024); aider's whole-vs-diff data spans GPT-3.5 to Sonnet-3.5. 2026 frontier models are drastically better at patch compliance, so over-investing in fuzzy recovery machinery fights the last war — keep the forgiving-applier ladder small and instrumented, and let telemetry justify each rung.
- Silent mis-application: aider's >80%-similarity fuzzy match and aggressive whitespace recovery can apply a hunk to the wrong location without error. In a no-sandbox trusted-host tool that may auto-commit, a silently wrong edit is worse than a failed edit. Default to fail-with-hint; make fuzzy application opt-in and always shown in the diff.
- No-sandbox blast radius: PolicyEngine ASK fatigue is real — if too many prompts fire, users will blanket-ALLOW and the only safety layer evaporates. Curate a small high-signal ASK set (writes outside workspace, network, recursive delete, git push) and DENY-list the catastrophic tail, mirroring SWE-agent's 'guardrails hasten recovery' finding at the policy level.
- Corporate gateway constraints: the Responses-compatible gateway may lack prompt caching, may truncate long tool observations, or serve models with different edit-format competence than personal OpenAI. Condenser cost math (OpenHands' 2x saving assumed caching) and per-backend edit-capability tiers must be validated against the actual gateway, not assumed.
- Offline-wheel dependency creep: tree-sitter grammars, native linters, and any summarizer-model dependency all complicate pip --no-index installs on locked-down Windows. Prefer stdlib (ast, py_compile, difflib) implementations; every native wheel added is an install-failure mode.
- Event-log schema drift: OpenHands' condensation-as-event design only works because views are derived deterministically from the log. Foundry's versioned JSONL must version event schemas from day one (including future Condensation/masking events), or resumed old sessions will replay into prompts the model never actually saw, breaking both resume and audit.
- Auto-commit in corporate repos: aider-style auto-commits can trigger commit hooks, signing requirements, and branch protections, and pollute shared history. Default auto-commit OFF; snapshot via refs/stash instead, and never touch the index without an explicit policy ALLOW.
