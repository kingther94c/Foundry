# Windows/Python constraints

## Summary

Windows + Python 3.12 lets Foundry hit its "offline wheel, minimal deps" bar with an almost pure-stdlib runtime; every heavy dependency the ecosystem usually reaches for (keyring, psutil, httpx/requests) has a ctypes- or stdlib-equivalent that is actually MORE correct for this use case. Credentials: DPAPI via ctypes (CryptProtectData/CryptUnprotectData, CRYPTPROTECT_UI_FORBIDDEN) beats keyring — keyring's Windows backend drags in pywin32-ctypes plus the jaraco.* trio (→ more-itertools), and its Credential Manager vault caps blobs at CRED_MAX_CREDENTIAL_BLOB_SIZE = 2560 bytes, which a serialized OAuth token set (refresh + id_token JWT) can exceed. Process-tree kill: a ctypes Job Object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE + TerminateJobObject is the only mechanism that both kills grandchildren atomically and — critically — releases inherited pipe handles so Popen.communicate() cannot hang on an orphan; taskkill /T and psutil both walk parent-PID snapshots and lose orphaned/ PID-reused branches.

Encoding is the sharpest Chinese-locale edge: PEP 686 (UTF-8 default) is Final but targets Python 3.15, so on 3.12 subprocess text-mode decodes with cp936 on zh-CN Windows while modern dev tools (git, node, python-with-PYTHONUTF8) emit UTF-8 into pipes — capture bytes, decode UTF-8-first with an OEM-codec fallback, inject PYTHONUTF8=1/PYTHONIOENCODING into children, and hard-code encoding="utf-8" on every open() (the JSONL session store must never depend on locale). Path containment needs os.path.realpath (resolves symlinks+junctions and expands 8.3 short names since 3.8 via GetFinalPathNameByHandle) + normcase + commonpath, plus os.lstat().st_reparse_tag / os.path.isjunction (new in 3.12) to detect junctions that islink() misses; watch realpath's non-strict mode silently leaving components unresolved on access-denied, ADS colons, reserved device names (os.path.isreserved is 3.13+, so hand-roll), and LongPathsEnabled being off on managed machines.

For HTTP, stdlib http.client is the right call and not just for size: ssl.create_default_context() loads the Windows CA/ROOT system stores, so corporate MITM proxies with a machine-installed CA work out of the box, whereas httpx (7-wheel tree: httpcore, h11, anyio, certifi, idna, typing_extensions) and requests (5 wheels) default to certifi and fail behind such proxies until users discover SSL_CERT_FILE/REQUESTS_CA_BUNDLE. SSE over an OpenAI-Responses gateway is line-oriented reading of a chunked response — ~60 lines, no library. Distribution: pip-compile --generate-hashes → pip download --only-binary :all: (with --platform win_amd64/--python-version 312 if cross-building) → pip install --no-index --find-links --require-hashes; build the wheel with hatchling (backend never ships in the wheelhouse, so its build-machine deps are free). TUI: rich (pure-python, +markdown-it-py/mdurl/pygments = 4 wheels) plus optionally prompt_toolkit (+wcwidth = 2 wheels); skip textual (~9 wheels, app framework Foundry doesn't need) — but escape model/tool output before feeding it to rich and strip OSC/ANSI from untrusted tool stdout.

## Designs

### Credential storage (OAuth refresh tokens) on Windows
- **How**: The keyring package's Windows backend (WinVaultKeyring) stores secrets in Windows Credential Manager via pywin32-ctypes, and keyring's pyproject additionally requires jaraco.classes, jaraco.functools, jaraco.context (which pull more-itertools) — roughly 5-6 extra wheels. Credential Manager itself caps CredentialBlobSize at CRED_MAX_CREDENTIAL_BLOB_SIZE = 5*512 = 2560 bytes (learn.microsoft.com wincred CREDENTIALA doc). Raw DPAPI (CryptProtectData/CryptUnprotectData in Crypt32.dll) encrypts arbitrary-size blobs keyed to the user's logon credential, needs ~50 lines of ctypes, adds a MAC, and requires LocalFree on the returned DATA_BLOB.pbData; CRYPTPROTECT_UI_FORBIDDEN suppresses any UI (the PromptStruct flow is deprecated, removal Feb 2027 — always pass NULL); CRYPTPROTECT_LOCAL_MACHINE would widen decryption to every user on the machine.
- **Takeaway**: ADOPT: DPAPI via ctypes. Store the CryptProtectData output (base64) in %LOCALAPPDATA%\Foundry\auth.json, written atomically via tempfile + os.replace, decrypted with CryptUnprotectData at load. Zero dependencies, no 2560-byte ceiling (token payloads with JWT id_tokens can exceed it), and the same user-scoped trust model Credential Manager gives anyway (any same-user process can decrypt — that is V1 trusted-host, disclose it; note Codex stores auth.json in PLAINTEXT, so DPAPI is strictly stronger). Skip the optional entropy parameter — the entropy would have to live on disk beside the blob, adding obfuscation not security. Gotchas: a forced admin password reset on a LOCAL account invalidates DPAPI master keys → always implement a graceful 'decrypt failed → re-run login flow' path; roaming profiles can decrypt on other domain machines (fine). AVOID keyring: 6 wheels to bloat the offline wheelhouse for a worse blob limit.

### Killing the run_command subprocess TREE on cancel/timeout
- **How**: Job Objects: CreateJobObjectW → SetInformationJobObject(JobObjectExtendedLimitInformation) with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE → subprocess.Popen(...) → AssignProcessToJobObject(hJob, int(proc._handle)); children created via CreateProcess are auto-associated with the job; TerminateJobObject kills every process in the job in one syscall, and kill-on-close guarantees the tree dies even if Foundry itself crashes (last handle closed → tree terminated). Nested jobs are supported since Windows 8/Server 2012, so this works even when Foundry already runs inside a CI/job. taskkill /T /F and psutil.children(recursive=True) both reconstruct the tree from a parent-PID snapshot: they lose grandchildren whose intermediate parent already exited and can mis-kill on PID reuse; psutil is additionally a C-extension wheel. For graceful cancel, subprocess docs: CREATE_NEW_PROCESS_GROUP at spawn enables proc.send_signal(signal.CTRL_BREAK_EVENT) to the group (CTRL_C_EVENT cannot target another group).
- **Takeaway**: ADOPT: pure-ctypes Job Object per run_command invocation (kernel32 only — no deps): create job with KILL_ON_JOB_CLOSE, Popen with creationflags=CREATE_NEW_PROCESS_GROUP, assign immediately, on cancel send CTRL_BREAK_EVENT, wait a grace period, then TerminateJobObject. The job also fixes the classic Windows hang where proc.kill() leaves a grandchild holding the inherited stdout pipe so communicate() never returns EOF — job termination closes those handles. Gotchas: (1) tiny race between Popen return and AssignProcessToJobObject where the child could spawn a grandchild outside the job — stdlib can't do CREATE_SUSPENDED cleanly (Popen closes the thread handle so you can't ResumeThread) nor PROC_THREAD_ATTRIBUTE_JOB_LIST; accept and document the millisecond window; (2) do NOT set BREAKAWAY_OK limits — leaving them unset prevents escape; (3) CREATE_NEW_PROCESS_GROUP means the child ignores the console's own Ctrl+C, which is what you want since Foundry mediates cancellation. AVOID taskkill/psutil as the primary mechanism; keep `taskkill /T /F /PID` only as a last-ditch fallback if job APIs error.

### Console encoding on Chinese-locale Windows (cp936/GBK vs UTF-8)
- **How**: PEP 686 (make UTF-8 mode the default) is Status: Final but targets Python 3.15 — on 3.12 the locale encoding still wins: open() and subprocess text=True decode with locale.getpreferredencoding(False) = cp936 on zh-CN Windows unless UTF-8 mode (-X utf8 / PYTHONUTF8=1, PEP 540) is on. PEP 528/529 already made console I/O and the filesystem encoding UTF-8 regardless. Child processes are inconsistent: modern tools (git, node, ripgrep, cargo, Python with PYTHONUTF8) write UTF-8 to pipes; cmd.exe builtins and legacy tools write the OEM/ANSI code page (both 936 on zh-CN); powershell.exe 5.1 encodes per [Console]::OutputEncoding (OEM) while pwsh 7 uses UTF-8. Python ships a Windows-only 'oem' codec (since 3.6) and the docs warn that setting PYTHONUTF8=1 machine-wide affects every Python app.
- **Takeaway**: ADOPT a bytes-first capture policy in run_command: never pass text=True/encoding to Popen; capture raw bytes, decode UTF-8 with errors='replace' as primary, and if the decode produced U+FFFD replacements, retry with the stdlib 'oem' codec (falls back to cp936 on zh-CN) and keep whichever has fewer replacements. Persist the RAW bytes (or base64) in the JSONL session store so a bad guess is re-decodable later. Inject PYTHONUTF8=1 and PYTHONIOENCODING=utf-8 into the child environment so all Python descendants emit UTF-8; run Foundry itself in UTF-8 mode via its entry-point (or `-X utf8`) rather than telling users to set PYTHONUTF8 globally. Hard-code encoding='utf-8' on every open() in Foundry (session store, config, apply_patch file I/O — for source files, detect/preserve existing encoding+BOM instead of assuming locale). AVOID: `chcp 65001` hacks (per-console global state, breaks legacy apps, doesn't govern pipe writers) and trusting locale.getpreferredencoding for anything durable. Turn on -X warn_default_encoding (PEP 597 EncodingWarning) in CI to catch missing encoding= args.

### Path safety for workspace-containment (junctions, reparse points, long paths, case)
- **How**: Detection: os.lstat() on Windows exposes st_file_attributes (test stat.FILE_ATTRIBUTE_REPARSE_POINT) and st_reparse_tag (compare against stat.IO_REPARSE_TAG_SYMLINK / IO_REPARSE_TAG_MOUNT_POINT / IO_REPARSE_TAG_APPEXECLINK, all added 3.8; APPEXECLINK is the Microsoft Store python.exe shim). os.path.islink() is False for junctions; os.path.isjunction()/Path.is_junction() were added in exactly 3.12. Resolution: since 3.8 os.path.realpath resolves symlinks AND junctions via GetFinalPathNameByHandle — which also canonicalizes 8.3 short names (PROGRA~1) — but in default non-strict mode it 'is evaluated up to the first component that ... raises OSError' (access denied, etc.) and appends the rest UNRESOLVED; strict=True re-raises. Long paths: python.exe's manifest is longPathAware, but paths >260 chars still require HKLM\...\FileSystem\LongPathsEnabled=1 (docs.python.org/3.12/using/windows.html); \\?\-prefixed paths bypass MAX_PATH but disable Win32 normalization. NTFS is case-insensitive by default but per-directory case-sensitivity exists (fsutil/WSL).
- **Takeaway**: ADOPT this containment recipe for every tool that touches paths: canonicalize root once (realpath, strict), canonicalize candidate with realpath, compare via os.path.normcase on both + os.path.commonpath — never a naive startswith (8.3 names, case, and / vs \ all defeat it) and never pathlib.is_relative_to alone (purely lexical). Additionally reject or flag any path whose lstat shows FILE_ATTRIBUTE_REPARSE_POINT with a tag other than expected, so a junction inside the workspace pointing at C:\Users can't smuggle reads/writes out — check each component below the root, not just the leaf. Hand-roll extra Windows validation on 3.12: reserved device names (CON, NUL, COM1-9, LPT1-9, even 'NUL.txt' — os.path.isreserved only landed in 3.13), trailing dots/spaces (silently stripped by Win32), ADS colons ('file.txt:stream'), and drive-relative forms ('C:foo'). Long paths: don't assume LongPathsEnabled on managed corp machines — catch FileNotFoundError/OSError on deep node_modules trees and surface a targeted error (and note git needs core.longpaths=true independently). Accept the check-then-act TOCTOU race explicitly in V1's trusted-host threat model docs.

### Offline wheel distribution and build backend
- **How**: pip's hash-checking mode (pip.pypa.io/en/stable/topics/secure-installs/): put --hash=sha256:... on every requirement; the mode activates if any requirement has a hash, then REQUIRES all requirements pinned (==/URL/path) and hashes for all transitive deps; --require-hashes forces it. It composes with pip download and pip wheel. Backends: hatchling's runtime deps are packaging, pathspec, pluggy, tomlkit, trove-classifiers (+tomli <3.11); flit-core is zero-dep; setuptools is the legacy heavyweight. For a wheel-only install (--no-index --find-links), the build backend is never invoked on the target machine — it only matters on the build machine.
- **Takeaway**: ADOPT: requirements.in → `pip-compile --generate-hashes` (or `uv pip compile --generate-hashes`) → locked requirements.txt → on a connected machine `pip download -r requirements.txt -d wheelhouse --require-hashes --only-binary :all:` → target machine `pip install --no-index --find-links wheelhouse --require-hashes -r requirements.txt Foundry-x.y.z-py3-none-any.whl`. If the download machine differs from the target profile, pass --platform win_amd64 --implementation cp --python-version 3.12 --abi none/cp312 (these flags require --only-binary :all:). Keep the dep list pure-python so every wheel is py3-none-any and one wheelhouse serves all Windows boxes. Gotchas: one sdist-only transitive dep breaks the offline story (it would need a compiler + backend on target) — the --only-binary flag turns that into a loud early failure; hash-pinning freezes security patches, so schedule a re-lock cadence; ship a supported pip version note (very old corporate pips predate modern hash/resolver behavior). Build backend: ADOPT hatchling in [build-system] with a pinned version for reproducibility (nice defaults, src layout, no setup.py); flit-core is the acceptable minimalist alternative; setuptools buys nothing here. This choice costs zero at install time.

### HTTP client for OpenAI/gateway SSE streaming
- **How**: Measured dep trees: httpx → certifi + httpcore==1.* + anyio + idna; httpcore → certifi + h11; anyio → idna (+exceptiongroup <3.11, typing_extensions <3.15) ⇒ ~7 wheels. requests → charset_normalizer + idna + urllib3 + certifi ⇒ 5 wheels. stdlib http.client ⇒ 0 wheels; it transparently de-chunks Transfer-Encoding: chunked, so SSE is `for line in response:`-style reads until blank line; HTTPSConnection.set_tunnel() implements proxy CONNECT, and urllib.request.getproxies() reads HTTPS_PROXY/NO_PROXY env AND the Windows registry Internet Settings. TLS trust: ssl docs — 'On Windows [load_default_certs] loads CA certs from the CA and ROOT system stores', which create_default_context() uses when no cafile is given; certifi-based httpx/requests instead trust only the Mozilla bundle unless SSL_CERT_FILE / REQUESTS_CA_BUNDLE / a truststore-backed context is configured.
- **Takeaway**: ADOPT: a small internal module on stdlib http.client/ssl — one class handling (1) POST JSON, (2) SSE iterator with per-read socket timeout, (3) proxy support via getproxies() + set_tunnel(host, port, headers={'Proxy-Authorization': basic}) honoring NO_PROXY, (4) ssl.create_default_context() so a corporate MITM CA installed in the Windows ROOT store works with ZERO configuration — this is the decisive advantage for the corporate-gateway backend, where certifi-based clients are the #1 'SSL: CERTIFICATE_VERIFY_FAILED' support ticket. Offer FOUNDRY_CA_BUNDLE/SSL_CERT_FILE overrides for PEM-file shops. Keep scope honest: exactly two backends, no redirects-following, simple bounded retry with jitter, connection-per-request is acceptable at agent call rates (optionally reuse HTTPSConnection per host). Gotchas: no total-read deadline in http.client — enforce staleness via socket timeout raising mid-read; HTTP/1.1 only (irrelevant for SSE); NTLM/Kerberos (Negotiate) proxies are NOT supported by stdlib, requests, OR httpx without extra packages — detect 407 with Negotiate and emit an actionable error. AVOID requests (5 wheels, no async, certifi trap, no real advantage) ; httpx is the fallback if the team refuses to own ~300 lines, but budget 7 wheels and document the CA-bundle trap.

### TUI/CLI layer
- **How**: Wheel-count reality (all pure-python): prompt_toolkit → wcwidth only (2 wheels); rich → markdown-it-py (→ mdurl) + pygments (4 wheels; rich handles legacy-console color via its own win32 code and works in Windows Terminal/conhost); textual → rich + markdown-it-py[linkify] + mdit-py-plugins + typing-extensions + platformdirs + pygments (~9 wheels) plus a full reactive app framework. Pure stdlib requires manually enabling VT sequences on legacy conhost via ctypes SetConsoleMode(ENABLE_VIRTUAL_TERMINAL_PROCESSING=0x0004) and hand-rolling wrapping/highlighting/spinners.
- **Takeaway**: ADOPT rich as the render layer: 4 pure-python wheels buys markdown rendering of model output, syntax-highlighted diffs for apply_patch previews, Live/spinner for streaming, and correct east-asian-width handling — exactly the agent-CLI feature set, and it degrades sanely when stdout is piped (Console auto-detects; force_terminal only for tests). ADD prompt_toolkit (one extra wheel: wcwidth) only when the ASK approval flow needs more than input()/y-n — history, key bindings, async prompt during streaming; guard it behind sys.stdin.isatty() since it needs a real console. AVOID textual for V1: doubles the wheelhouse and imposes an app-framework architecture on what is a scrolling transcript + prompts; revisit for V2 if a panes UI is wanted. AVOID pure-stdlib-only: the ctypes VT dance is easy but you will reimplement wrapping/width/highlighting badly. Two mandatory hardening rules regardless: pass model/tool text through rich.markup.escape() (or print with markup=False) so emitted [bold]/[link] tags can't inject, and strip raw ANSI/OSC escape sequences (OSC 52 clipboard write, window-title, cursor tricks) from untrusted tool stdout before rendering — terminal escape injection is a real exfil channel in agent CLIs.


## Risks

- DPAPI blobs become undecryptable after an admin-forced password reset on local (non-domain, non-Microsoft) accounts — Foundry must treat CryptUnprotectData failure as 'logged out' and re-run the OAuth flow, never as a corrupt-store fatal error.
- Job-object assignment happens after Popen returns (stdlib cannot use CREATE_SUSPENDED or PROC_THREAD_ATTRIBUTE_JOB_LIST), leaving a milliseconds-wide race in which a child could spawn a grandchild outside the job; also verify behavior on hosts where Foundry itself already runs inside a job (needs Win8+ nested jobs — fine on Win10/11 but assert at startup).
- UTF-8-first decoding can still mojibake genuinely mixed streams (cmd.exe builtin banner in GBK followed by git UTF-8 output in the same capture); mitigation is storing raw bytes in the SessionStore so transcripts are re-decodable — if only decoded text is persisted, the information is destroyed.
- os.path.realpath in default non-strict mode silently appends unresolved components after the first access-denied error, so a containment check can pass on a path whose tail still contains a hostile junction; the per-component lstat/reparse-tag walk is required, and check-then-act TOCTOU remains inherent to V1's no-sandbox model and must be stated in the threat model.
- LongPathsEnabled is off by default and often locked by corporate group policy; even when Python succeeds, spawned tools fail independently (git needs core.longpaths=true), so deep node_modules-style trees will produce confusing partial failures.
- The offline wheelhouse silently breaks the day any pinned dep publishes a Windows-incompatible release or an sdist-only version, and --require-hashes freezes security fixes; a scheduled re-lock/re-download pipeline is operationally required, not optional.
- Corporate proxies requiring NTLM/Kerberos (407 Proxy-Authenticate: Negotiate) are unsupported by stdlib, requests, and httpx alike without extra packages — probe for this early in pilot deployments because it invalidates the whole HTTP layer choice if widespread, and PAC-file-only environments need HTTPS_PROXY to be set manually.
- Terminal escape-sequence injection: model output and tool stdout rendered through rich can carry rich markup tags and raw OSC/ANSI sequences (OSC 52 clipboard exfil, title spoofing); sanitize before rendering — this is a security bug class, not cosmetics.
- If keyring is ever adopted later for parity with other platforms, its Windows Credential Manager backend caps secrets at 2560 bytes (CRED_MAX_CREDENTIAL_BLOB_SIZE), which will truncate/reject larger serialized token sets that the DPAPI file store handled fine.
